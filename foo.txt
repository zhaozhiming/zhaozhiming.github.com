⏺ 现在我有了完整的信息，来给你说清楚两者的区别。

  ---
  两种安装方式的对比

  官方 Plugin 安装方式 (/plugin install superpowers@claude-plugins-official)

  Claude Code 会：
  1. 从 GitHub 拉取并缓存到
  ~/.claude/plugins/cache/<marketplace>/<plugin>/<版本号>/
  2. 在 settings.json 的 enabledPlugins 中注册
  3. 在 installed_plugins.json 里记录版本号和 gitCommitSha

  installPath:
  ~/.claude/plugins/cache/claude-plugins-official/superpowers/1.0.0/

  软链接安装方式（你现在用的）

  ~/.claude/skills/using-superpowers  →  ../../.agents/skills/using-superpowers

  手动 clone repo 到 ~/.agents/skills/，然后在 ~/.claude/skills/
  里建软链接。Claude Code 完全不知道这是"插件"，只当作普通的本地 skills 目录。

  ---
  核心区别

  ┌─────────────────┬────────────────────────────┬──────────────────────────┐
  │      维度       │      官方 Plugin 方式      │        软链接方式        │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ 更新            │ /plugin update 自动更新    │ 手动 git pull            │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ 版本管理        │ 有版本号 + gitCommitSha    │ 无，直接用当前 HEAD      │
  │                 │ 记录                       │                          │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ 隔离性          │ 每个版本独立目录，可回滚   │ 直接链接源码，无版本隔离 │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ settings.json   │ 需要在 enabledPlugins 注册 │ 不需要                   │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ Claude Code     │ 完整插件生命周期管理       │ 透明，仅读文件           │
  │ 感知            │                            │                          │
  ├─────────────────┼────────────────────────────┼──────────────────────────┤
  │ 使用时效果      │ 完全一样                   │ 完全一样                 │
  └─────────────────┴────────────────────────────┴──────────────────────────┘

  结论：对 Claude 的实际行为（调用 skill
  时读到的内容）没有任何区别。区别只在维护层面——软链接方式你可以随时修改
  ~/.agents/skills/
  里的内容立即生效，更灵活；官方方式更规范、有版本管控，但修改需走插件更新流程。

  你现在的软链接方式非常适合想自定义或调试 skill 内容的场景。

⏺ 你说得完全正确。官方 plugin 系统支持四种组件，软链接只能覆盖其中一种：

  ---
  官方 Plugin 能装的组件

  plugin-name/
  ├── .claude-plugin/plugin.json   # 清单
  ├── skills/          # ✅ 软链接能覆盖
  ├── commands/        # ❌ 软链接无法覆盖 → 注册 /slash-command
  ├── agents/          # ❌ 软链接无法覆盖 → 注册子 Agent 类型
  └── hooks/
      ├── hooks.json   # ❌ 软链接无法覆盖 → 自动注册 Hook
      └── stop-hook.sh

  真实案例 —— 你机器上的 ralph-loop 插件：
  - commands/ralph-loop.md → 注册了 /ralph-loop 命令
  - hooks/hooks.json → 自动在 Stop 事件注册了一个 shell hook

  ---
  对 Superpowers 的具体影响

  using-superpowers 的 skill 描述写的是：

  ▎ "Use when starting any conversation"

  但用软链接安装后，没有任何机制强制在每次会话开始时自动触发它，需要 Claude
  自己"记得"去调用，或者用户手动 /using-superpowers。

  如果通过官方 plugin 安装，Superpowers 可以注册一个会话开始的
  Hook，每次对话自动执行，不依赖 Claude 的主动意识。这就是你今天问"有没有加载
  superpower"的根本原因——软链接装的 skill 没有 hook 做保障。

  │ Slash Commands │ ❌ 需手动建 ~/.claude/commands/ │ ✅ 自动注册       │
  ├────────────────┼─────────────────────────────────┼───────────────────┤

  │ Hooks          │ ❌ 需手动改 settings.json       │ ✅ 自动注册并执行 │
  └────────────────┴─────────────────────────────────┴───────────────────┘

⏺ 你的理解基本正确，但有一个细节值得补充。

  你说的灵活性是真实存在的 —— 软链接方式确实让 using-superpowers 只在 prompt
  命中时才触发，而不是每个 session 无条件执行。对于很多不需要 skill
  的简单对话，这反而避免了不必要的开销。

  但有一个反面：using-superpowers 的设计意图明确写在描述里：

  ▎ "Use when starting any 
  ▎ conversation"，并且要求在包括澄清性问题在内的任何回复之前都先调用

  它的设计哲学是"无条件、每次都加载"，hook
  是实现这个意图的技术保障。软链接方式把决策权交给了 Claude 的判断，而 Claude
  可能判断失误（就像今天你发现的那样 —— 我没有主动调用它）。

  所以准确的说法是：

  ┌──────────────────┬───────────────────────┬─────────────────────────┐
  │                  │   Plugin Hook 方式    │       软链接方式        │
  ├──────────────────┼───────────────────────┼─────────────────────────┤
  │ 行为             │ 每次 session 强制执行 │ Claude 判断后执行       │
  ├──────────────────┼───────────────────────┼─────────────────────────┤
  │ 是否符合设计意图 │ ✅ 完全符合           │ ⚠️ 取决于 Claude 的判断 │
  ├──────────────────┼───────────────────────┼─────────────────────────┤
  │ 灵活性           │ 低（总是触发）        │ 高（按需触发）          │
  ├──────────────────┼───────────────────────┼─────────────────────────┤
  │ 可靠性           │ 高                    │ 低（可能漏掉）          │
  └──────────────────┴───────────────────────┴─────────────────────────┘

  如果你希望 using-superpowers 真正做到"每次对话都生效"，最简单的办法不是装官方
  plugin，而是在你的全局 CLAUDE.md 里加一句明确的指令，这比 hook
  还可靠，因为它直接进入 system prompt。
